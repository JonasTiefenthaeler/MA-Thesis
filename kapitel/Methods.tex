\chapter{Methods}\label{chap: Methods}

For this Thesis the high-order \acrfull{sem} code NEKO is used.
Neko is an open-source \acrfull{cfd} solver, that is based on the older Nek5000 \acrshort{cfd} solver done by \cite{fischerNek500WebPage} in the nineties.
The portable framework Neko is written in modern Fortran in an object-oriented manner and is mainly focused on incompresible flow simulations \citep{janssonNekoModernPortable2024}.
Only \acrfull{dns} will be performed in this work, however \acrfull{les} models are also implemented in NEKO.


\section{Simulation setup}\label{sec: Simulation setup}
For this study, the canonical setup of the pipe is used.
In the pipe azimuthal periodicity is given by default \citep{yaoDirectNumericalSimulations2023}.\\
The dimensions of the rough domain is $L_r \times L_\theta \times L_z = 1 \times 2\pi \times 8\pi$, with the radius $R$ is set to $1 \hat{=}$ unity, while the smooth validation domains are shortened to $L_z = 4\pi$ to save on computational time.
$R$ denotes the mean radius of the pipe in rough setups, hence the distance from the virtual origin to the pipe center.\\
For the \acrfull{bcs}, the Dirichlet \acrshort{bc} at the pipe wall is used, which states that the fluid at the wall  moves with the same velocity as the wall itself, in this setup all velocities are set to zero at the wall: $u_i = 0 \ \text{for}\ y = 0$.
Since the streamwise direction is homogeneous in turbulent channel flow \citep{moinDIRECTNUMERICALSIMULATION1998}, a periodic boundary condition for the inflow and outflow of the pipe is used.
This means, that the velocities of the outflow are always equal to the velocities at the inflow: $u_{i_{l = 0}} = u_{i_{l=L_z}}$, which implies that fluid that leaves the domain at the outflow reenters the domain at the inflow.
Also, for the wall of the pipe, the impermeability condition is set.\\
The initial condition is important to support a fast transition to turbulence.
A fast transition to turbulence is favorable, since it saves computational resources.
This is achieved by having a basis of a laminar velocity profile, which is overlaid by large- and small scale disturbances, which are intended to disrupt the laminar flow field and support transition to turbulence.
The initial velocity field is taken from the NEKO example of the turbulent channel and ported to polar coordinates and altered, such that the divergence-free criterion $\nabla u_i = 0$, which is necessary to fulfill the conservation of mass \citep{popeTurbulentFlows2015}.\\
The bulk flow rate $U_b$ is defined in streamwise $z$ direction to be unity $=1$ and is kept constant.
To achieve the desired bulk velocity, the flow is driven by a pressure gradient $\Pi$.
To maintain a constant flow rate the pressure gradient $\Pi$ is varying in time to adjust for changing flow conditions, e.g.\ when turbulence develops.
Using \autoref{eq: viscous scaling units} t is also possible to compute $Re_\tau$ from $\Pi$  as described by \cite{demaioDirectNumericalSimulation2023}
\begin{equation} \label{eq: REtau from forcing}
    Re_\tau = \sqrt{\frac{\Pi}{2}}Re_b \quad \text{since} \quad \tau_w = \frac{R}{2}\Pi 
\end{equation}

\section{Generating rough surfaces}\label{sec:generating rough surfaces}
Surfaces in real-world engineering applications often exhibit irregular roughness.
In previous studies often scans of real-world surfaces are used, to perform the simulations, e.g. by \cite{thakkarInvestigationTurbulentFlow2017}, \cite{demaioDirectNumericalSimulation2023} and \cite{busseReynoldsnumberDependenceNearwall2017}.
This yields the advantage, that inherently the real world influence of surface roughness is investigated.
This method is however restricted by the available surface.
Also, the investigated surface parameters can not be directly controlled, but are a direct result of the chosen surface to be scanned.
In the present work, the surface roughness will be generated by an algorithm introduced by \cite{perez-rafolsGeneratingRandomlyRough2019}.
In the following section a brief description of the algorithm is given.

\subsection{Surface generation algorithm}\label{subsec: Surface generation algorithm}

The idea behind the algorithm by~\cite{perez-rafolsGeneratingRandomlyRough2019} is, that a realistic surface topography needs a height distribution, as well as a spatial distribution.
To that extend, two main input parameters need to be specified.
To define the height distribution, a height probability distribution is chosen.
To define the spacial distribution, a power spectrum is used.
Using the probability distribution and the power spectrum, two initial surfaces $Z_h$ and $Z_S$ are generated. 
The first surface $Z_h$ shows the desired probability distribution, but not necessarily the power spectrum.
The second surface $Z_s$ exhibits the power spectrum but not the probability distribution.
The algorithm iteratively corrects $Z_s$ and $Z_h$ to match each other, until a specified convergence is reached.
The iteration consists of two steps:
\begin{enumerate}
    \item Adjust the $Z_s$ using the formula $\hat{Z}_s^{i+1} = \hat{Z}_h^i \frac{|\hat{Z}_s^i|}{|\hat{Z}_h^i|}$, with the values denoted by $\hat{Z}$ representing their respective Fourier transforms.
    The inverse transform of $\hat{Z}_s^{i+1}$, $Z_s^{i+1}$, shows the specified power spectrum but a changed height probability distribution.
    \item Obtain a $Z_h^{i+1}$ by adjusting the height probability distribution of $Z_s^{i+1}$.
    This is achieved by rank ordering
\end{enumerate}
In this work, as the random distribution the Weibull distribution is used, with the probability density function
\begin{equation}\label{eq: Weibull distribution}
    f(z) = \frac{k}{\lambda} \left( \frac{z}{\lambda}\right)^{k-1} e^{-(z/k)^{k}}
\end{equation}
with $k$ being the shape factor and $\lambda$ representing the scale factor.
The used power spectrum is defined by
\begin{equation}\label{eq: Power spectrum}
    C(q) = \frac{S_q^2 \beta}{2\pi\left(\beta^2 + q_x^2+q_y^2\right)^{\frac{3}{2}}}
\end{equation}
with $S_q$ being the rms height and $\frac{1}{\beta}$ is the autocorrelation length, as described by \cite{perez-rafolsGeneratingRandomlyRough2019}.
The specific random distribution and power spectrum are chosen, since they are thoroughly tested by \cite{perez-rafolsGeneratingRandomlyRough2019}.
It shows, that reasonably fast convergence, as well as low absolute errors can be achieved.
It is important to note, that the two surfaces are not exactly the same, but similar within the bounds of a defined tolerance.
$Z_h$ will have the desired height probability distribution, but the power spectrum will deviate slightly within the capability of the algorithm and the defined tolerances.
Vice versa for $Z_s$.
It is chosen to use the surface $Z_h$ in this work.\\
To obtain a surface, which has the desired surface parameters, the correct input values for $k, \lambda, \beta$ and $S_q$ have to be found.
This is done using a quasi-Newton optimization algorithm implemented in the scipy.optimize python library.
The optimization algorithm changes the parameters within the parameterspace systematically, such that the target function is minimized.
The target function is defined to be the sum of the squared deviations of the considered surface parameters to their respective targets.
To dispose the random noise of the random number generator of the random distribution, the random seed is fixed throughout this process.\\

\subsection{Applying rough surfaces onto the mesh}\label{subsec: Generating rough mesh}

The algorithm described in section \ref{subsec: Surface generation algorithm} yields the height values for a plane surface.
This surface has to be mapped onto the pipe in such a way, that the same generated surface can be mapped onto different meshes with varying amounts of grid points.
%This leads to the fact, that the straightforward method, i.e. applying the height values of the generated surface points directly onto the pipe mesh is not applied in this work.
The used approach relies on the fact that every surface topography can be decomposed into a multitude of $\sin$ and $\cos$ waves using a Fourier transform \citep{perez-rafolsGeneratingRandomlyRough2019}.
The decomposed values are the Fourier coefficients, which can be seen as a weight given for each mode.
By recombining the extracted modes, the surface can be recreated independently of the simulation mesh.
The Fourier coefficients are extracted by taking the real and imaginary part  of the Fourier transform of the generated rough surface, such that $A(m,n) = \operatorname{Re}\left(\hat{Z}_h\right)$ and $B(m,n) = \operatorname{Im}\left(\hat{Z}_h\right)$\\
This decomposition and recreation is only exact, if an infinite number of modes is used.
%This is however only relevant for regular surfaces.
%Since the surfaces generated by the algorithm described in section \ref{subsec: Surface generation algorithm} are defined with a finite amount of modes (that is chosen by the user), this amount of modes is sufficient for the recreation of the surface.
With these parameters, the height function for the rough surface at each individual point can be defined as
\begin{equation}\label{eq: height function}
    k(\theta,z) = \sum_{n,n}^{M,N} A(m,n)\cos(phase)- B(m,n)\sin(phase)
\end{equation}
with
\begin{equation}\label{eq: phase equation}
    phase = 2\pi\left(\frac{uz}{L_z} + \frac{vth}{L_{th}}\right)
\end{equation}
with $A(m,n)$ and $B(m,n)$ representing the Fourier coefficients, $m$ and $n$ the Fourier mode and $z, th$ the streamwise and azimuthal coordinate of the respective point.
$M$ and $N$ denote the total number of Fourier modes that are taken into account.

The total number of Fourier modes $M$ and $N$ changes the shape of the surface significantly.
A higher number of Fourier modes also includes higher wavenumber modes, which leads to "wavier" surfaces, with smaller roughness features. 
This however, leads to a higher grid resolution requirement, since~\cite{chungPredictingDragRough2021} states, that at least $12$ grid points per roughness feature are necessary, to sufficiently resolve the shape of the roughness feature.\\
This height function \autoref{eq: height function} yields the recreation of the rough surface, which is applied on grid points at the wall.
However, a body fitted mesh is desired, which leads to the necessity, to create a scaling function for the grid points away from the wall.
The roughness function should be applied onto the mesh in the near wall region of the domain, while the inner region stays unaffected \citep{chanSystematicInvestigationRoughness2015}.
The used function for this purpose is
\begin{equation}\label{eq: roughness scaling function}
    r_{shift} = r + \frac{r - r_{crit}}{R - r_{crit}} * k(\theta,z) 
\end{equation}
with $r_{shift}$ representing the amout of necessary radial shift of the respective point, $ 0 < r_{crit} < 1$ the minimal radius, at which the grid points are shifted, $R$ the maximum radius of the smooth pipe mesh and $r$ the radial position of the point to be shifted.
This function scales the magnitude of shift applied to each grid point linearly between the outer pipe radius of the original smooth pipe and $r_{crit}$, from one to zero.
This method results in a body fitted mesh, where the boundaries of the mesh represent the roughness features.
Furthermore, the near wall mesh refinement is kept.\\
The points are only shifted in radial direction.
Since the GLL points are distributed onto the mesh before the roughness is applied, the GLL distribution is not exact after the rough deformation.
Since the shift is of small magnitude, the effect is assumed to be small.
A test on the influence on the simulation results is beyond the scope of this work.

\section{Postprocessing}\label{sec: Postprocessing}

In order to be able to work with the obtained data by the \acrshort{dns}, the data has to be postprocessed.
In this work, this is mainly done by using PySEMTools, which is a open source Python package, to postprocess \acrshort{sem} data on hexahedra high-order elements \citep{perezPySEMToolsLibraryPostprocessing2026}.\\
It is possible to obtain fluid statistics from multiple instantaneous fields.
Neko has the capability to produce statistics files, in which the data is averaged in time and in one or more spacial directions of choice during runtime. 
In this work, no spacial averaging was chosen to be performed by Neko, so the statistics files contain 3D data that is only averaged in time.
In order to be able to generate first- and second order statistics of the turbulent flow, this data has to be further processed.
The typical workflow is as follows:
\begin{itemize}
    \item In case multiple files exist that contain statistics data, average them to obtain a single time averaged field
    \item Interpolate the averaged data from the \acrshort{sem} mesh to user defined interpolation points
    \item Calculate the desired values, e.g.\ velocity profiles and turbulent budgets, based on the interpolated data
    \item Further average the 3D data in space, if desired
\end{itemize}
To be able to process data of rough cases properly, various modifications had to be made to the process, compared to a smooth case.

The approach used in this work is to map the \acrshort{dns} domain, as well as the interpolation points into a computational domain.
In the computational domain, the simulation domain is mapped from the rough shape into a smooth pipe, while the interpolation points are mapped such that they are at the respective positions of concentric circles in the physical domain.
For the rough simulation domain, is achieved by applying the inverse of the \autoref{eq: roughness scaling function} onto the rough mesh using the height functions \autoref{eq: height function} and \autoref{eq: phase equation}.
The inverse of \autoref{eq: roughness scaling function} is
\begin{equation}
     surf_{inverse} = \frac{1.0}{(1.0 + \frac{surf_{change}}{pipe_R - r_{crit}})} * (mesh_{change} + \frac{r_{crit}}{pipe_R - r_{crit}} * surf_{change})
\end{equation}

\section{Simulation Mesh}
The simulation mesh must have enough grid points to be able to correctly resolve the physics of turbulence.
Since the turbulent scales are decreasing near the wall and the viscous sublayer needs to be resolved, also the grid resolution near the wall needs to be refined.
Vice versa, the mesh can be coarsened towards the pipe center, without sacrificing correct results.
The simulation mesh is generated using Gmsh \citep{Gmsh}.
