\section{Generating rough surfaces}\label{sec:generating rough surfaces}

Surfaces in real-world engineering applications often exhibit irregular roughness.
In previous studies often scans of real-world surfaces are used, to perform the simulations, e.g. by \cite{thakkar_investigation_2017}, \cite{de_maio_direct_2023} and \cite{busse_reynolds-number_2017}.
This yields the advantage, that inherently the real world influence of surface roughness can be investigated.
This method is however very restricted by the number of surfaces and hence surface parameters, that can be tested.
Also, the investigated surface parameters can not be directly controlled, but are a direct result of the chosen surface to be scanned.
In the present work, the surface roughness will be generated by an algorithm introduced by \cite{perez-rafols_generating_2019}.

\subsection{Surface generation algorithm}\label{subsec: Surface generation algorithm}

The idea behind the algorithm by \cite{perez-rafols_generating_2019} is, that a realistic surface topography needs a height distribution, as well as a spatial distribution.
To that extend, two main input parameters need to be specified.
To define the height distribution, a height probability distribution needs to be specified.
To define the spacial distribution, a power spectrum is used.
Using the probability distribution and the power spectrum, two initial surfaces are generated. 
The first surface $Z_h$ shows the desired probability distribution, but not necessarily the power spectrum.
The second surface $Z_s$ exhibits the power spectrum but not the probability distribution.
The algortighm iteratively corrects $Z_s$ and $Z_h$ to match each other, until a specified convergence is reached.
The iteration consits of two steps:
\begin{enumerate}
    \item Adjust the $Z_s$ using the formula $\hat{Z}_s^{i+1} = \hat{Z}_h^i \frac{|\hat{Z}_s^i|}{|\hat{Z}_h^i|}$ , with the values deonted by $\hat{Z}$ representing their respective fourier transforms.
          The inverse transform of $\hat{Z}_s^{i+1}$, $Z_s^{i+1}$, shows the specified power spectrum but a changed height probability distribution.
    \item Obtain a $Z_h^{i+1}$ by adjusting the height probability distribution of $Z_s^{i+1}$.
          This is acheived by rank ordering
\end{enumerate}
In this work, as a random distribution the weibull distribution with the probability density function
\begin{equation}\label{eq: Weibull distribution}
    f(z) = \frac{k}{\lambda} \left( \frac{z}{\lambda}^{-1} \right)
\end{equation}
and the power spectrum
\begin{equation}\label{eq: Power spectrum}
    ps = asdfas
\end{equation}
The specific random distribution and power spectrum are chosen, since they are thoroughly tested by \cite{perez-rafols_generating_2019}.
It shows, that reasonably fast convergence, as well as low absolute errors can be acheived.
It is important to note, that the two surfaces are not exactly the same, but similar within the bounds of a defined tolerance.
$Z_h$ will always have the desired height probability distribution but the power spectrum will deviate slightly, within the capability of the algorithm.
Vice versa for $Z_s$.
It is chosen to use the surface $Z_h$ in this work.

\subsection{Applying rough surfaces onto the mesh}\label{subsec: Generating rough mesh}

The algorithm described in section \ref{subsec: Surface generation algorithm} yields the height values for a plane surface.
This surface has to be mapped onto the pipe in such a way, that the same generated surface can be mapped onto different meshes with varying amounts of grid points.
This leads to the fact, that the straightforward method, i.e. applying the height values of the generated surface points directly onto the pipe mesh is not applied in this work.
The used approach relies on the fact, that every surface topography can be decomposed into a multitude of $\sin$ and $\cos$ waves.
The decomposed values are the Fourier coefficients, which can be seen as a wheight given for each mode.
By recombining the extracted modes, the surface can be recreated.
This decomposition and recreation is only exact, if a infinite number of modes is used.
This is however only relevant for regular surfaces.
Since the surfaces generated by the algorithm described in section \ref{subsec: Surface generation algorithm} are defined with a finite amount of modes (that is chosen by the user), this amount of modes is sufficient for the recreation of the surface.
With these parameters, the height functions for the rough surface can be defined as
\begin{equation}\label{eq: height function}
    k(th,z) = \sum_{n,n}^{M,N} A(m,n)\cos(k_{th}m \cdot th + k_znz)- B(m,n)\sin(k_{th}m \cdot th + k_znz)
\end{equation}
with $A(m,n)$ and $B(m,n)$ representing the Fourier coefficients, $m$ and $n$ the Fourier mode, $k_{th}$ the azimuthal wavenumber with $k_{th} = \frac{2\pi}{L_{th}}$ and $k_z$ the streamwise wavenumber with $k_z = \frac{2\pi}{Lz}$.\\
This height function yield the recreation of the rough surface, which is applied as is at the grid points at the wall.
However, a body fitted mesh is desired, which leads to the necessity, to create a scaling function for the grid points away from the wall.
The roughness function should be applied onto the mesh in the outer region of the domain, while the inner region stays unaffected HIER VLT CHAN ZITIEREN.
The used function in this work is
\begin{equation}\label{eq: roughness scaling function}
    ys = sdafasf
\end{equation}
with $ 0 < r_{crit} < 1$ representing the minimal radius, at which the grid points are shifted.
This function scales the magnitude of shift applied to each grid point linearly between the outer pipe radius of the original smooth pipe and $r_{crit}$, from one to zero.

\section{Postprocessing}\label{sec: Postprocessing}

In order to be able to work with the obtained data by the \acrshort{dns}, the data has to be postprocessed.
In this work, this is mainly done by using PySEMTools, which is a open source Python package, to postprocess \acrshort{sem} data on hexahedra high-order elements \cite{perez_pysemtools_2026}.\\
The typical workflow is as follows:
\begin{itemize}
    \item In case multiple files exist that contain statistics data, average them to obtain a single averaged field
    \item Interpolate the averaged data from the \acrshort{sem} mesh to user defined interpolation points
    \item Calculate the desired values based on the interpolated data
    \item Further average the data, such that 2D or 1D plots can be generated
\end{itemize}
To be able to process data of rough cases properly, various changes had to be done compared to a smooth case.

\subsection{Postprocessing rough cases}\label{subsec: Postprocessing rough cases}

The Postprocessing of rough \acrshort{dns} data is not as straightforward as for smooth cases.
Two of the several conceivable workflows will be described in this section.

\subsubsection{Mapping Interpolation points to match the rough surface}\label{subsubsec: Mapping interpolation points}
In this approach, the interpolation points are mapped to match the rough surface of the \acrshort{dns}.
Due to the matching field, the interpolation points can be interpolated onto the \acrshort{dns} field with all points being found by the interpolator.
The main issue with this approach is the fact, that the interpolation points, which contain the data that is used in the further process, are not uniformly distributed in the radial direction.
This will lead to the situation, that data points that are interpolated at different radii will be treated as if they were at a comparable position.

\subsubsection{Inverse mapping \acrshort{dns} data and interpolation points}

The second approach is to introduce a computational domain for the data interpolation.
To map the \acrshort{dns} data into the computational domain it is mapped to a smooth pipe.
This is achieved by applying the inverse of the surface function to the rough surface.
The inverse of the rough surface function can be expressed as
\begin{equation}
     surf_{inverse} = \frac{1.0}{(1.0 + \frac{surf_{change}}{pipe_R - r_{crit}})} * (mesh_{change} + \frac{r_{crit}}{pipe_R - r_{crit}} * surf_{change})
\end{equation}
One must account for the fact, that for performing correct computations for first- and second-order statistics, data at points with a uniform distance from the pipe center are necessary.
